A few things you can do

Ready for the show

One switch puts FNSTools into Perform Mode. The overlays and helpers you use while building stop, the FNS button turns red, and everything your show uses keeps running.

Switch back and every tool returns as you left it. Perform Mode follows TouchDesigner's own (F1), and a show file saved with it on opens ready to go.

    Two ways to install

    One container goes into your project, you pick the tools from there, and only those get downloaded. Start from a download or from the picker on this site; either way, the updater keeps it current.

    Either

    Download and drop

    Drag FNSTools.tox into the root of a project. It is about 150 KB and arrives empty: the container you drop is where your tools will live.

    Then pulse Pick Tools and the picker opens inside TouchDesigner. Browse by category, follow any card through to its docs, and review the plan before anything is written to your project.

    Download
    What the picker actually does

    It downloads exactly the packages you ticked, plus the core registries they need, and verifies every file against the release manifest with sha256 before anything is installed.

    Nothing else is written.

    On the very first run it fetches the catalogue before it can show you anything, and says so while it does.

    Or

    Pick online and paste

    The same picker is on this site. Tick your tools, copy the one line it gives you, and paste it into the Textport of an open project.

    No download: the line fetches the container and your picks together and places the container in your project for you.

    Choose tools online →
    What the pasted line does

    It carries only the names you ticked. Release, URLs and hashes are read from the published manifest at paste time, so a line you copied earlier still installs the current release.

    It fetches the core registries, your selection and the container, verifies every file with sha256 before writing anything, then loads the container into the network you are in and hands it the selection to install.

    Then

    It stays current

    Each package carries its own version, and the updater compares it against the published one. Update the tools you use, leave the rest alone, and keep your settings across the swap.

    How updates work
    Where your settings live

    Preferences go into one aggregated JSON in your user palette, outside the project file, so the way you set a tool up follows you into the next project, and survives the next update.

    MIDI and OSC maps are the deliberate exception: they save into the project folder, so they travel with the show.

    Settings are preserved when a package is replaced. And the registries are promoted masters you can clone, so your own tools can sit on the toolbar, nav bar or OP menu too. How settings persistence works →

    Make it the default

    Save the project and set it as your startup file in Preferences → General → Startup File Mode. Every new project then opens with your tools already in it.

    On macOS

    Clipboard image paste is not available on macOS. Where the docs say Alt, press Cmd. Exceptions are called out per tool.

    Finding help later

    Alt-right-click (or Alt-middle-click) any toolbar icon to open that tool's page on this site. Option on macOS.

    Use it from a coding agent

    FNSTools ships an agent skill: a reference to every installed package, its promoted methods, quick-launch commands, hotkeys and settings, generated from the release you have. Run Install agent skill from the command palette and Claude Code, or any agent that reads the Agent Skills format, finds it in the project. How it works →

    Building a tool for FNSTools?

    The developer kit, FNSTools-DevKit.zip, holds the eleven registries, each as its own tox, with a README: the toolbar, the pane bars, the menus, the palette, the timeline, the settings file and the other surfaces a tool publishes into. Drop the ones your tool needs into a development project and build against them without installing the toolkit. It has no updater: take the kit of the release you target. Each registry's contract is on its page in the docs.
